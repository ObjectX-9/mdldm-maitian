# 健身猫功能教程制作

输入是用户的自录视频和功能说明。按视频里的真实操作复现该功能，交付三版视频、三平台共四张封面、三套发布文案，以及供返工复用的镜头清单。读取[系列规范](references/series.md)和[「今日建议怎么看？」完整案例](cases/today-advice/CASE.md)，新一期沿用这一套视觉、声音和文案结构。用户明确指定用现有录屏作成片素材时，从剪辑开始。

## 先看示范，再重录真机

1. 用 `ffprobe` 读取示范视频的时长、尺寸和方向，用 FFmpeg 先做一组带时间戳的预览帧，再在关键动作前后密集抽帧。逐张看画面，记录起始页面、按钮名称、手势、加载提示、返回结果和需要停留阅读的状态。用用户的功能说明确定本期要讲清楚什么，画面看不清的操作在镜像里确认。
2. 用 `phone-harness` 确认 Mac「iPhone 镜像」连接，遵循该技能的连接与操作规则。优先用演示账号或可公开的画面，避开会入镜的通知。用镜像窗口录制，固定窗口、方向与画面比例，保留指针。先短录并抽一帧确认裁切和指针，再从正确初态录一条完整操作。每一步等真实 UI 返回并稳定后再继续，保留动作前后的余量。保持原片可追溯。需要用户连接或授权镜像时，按 `phone-harness` 的交接流程处理。
3. 准确记录涉及的真实请求与页面状态。需要触发提交、购买、删除或其他外部写入才能演示时，先用演示环境或停在确认前。镜像连接待处理时，可以先整理示范视频的分镜。

## 剪辑和标记

1. 给新录原片按实际帧定位点击、加载开始、首个稳定结果和滑动结束。剪掉空等、重复操作及无关露出，保留触发动作和可辨认的结果。点击到结果之间保留必要的反馈和连续性，结果留足阅读时间。原始录屏、剪辑片段和标记可分别替换。
2. 在粗剪后再次抽帧。每处标记至少查看操作前、点击或滑动时、结果稳定后三帧；截取封面时也用该轮的真实画面。先在抽帧图上确认目标控件与可用留白，再绘制红圈、气泡、光标强调和运镜。
3. 用同一份镜头清单记录每个动作的原片时段、剪后时段、控件、手机有效画面内的归一化位置或框、气泡文字、运镜和停留时长、中文旁白及英文字幕。保存有效画面裁切与各版式的手机位置。剪掉等待或插入定格后，重新映射时间；根据裁切、缩放与运镜将标记位置投到各画幅，确保气泡尖尾和红圈跟着目标控件。把确认后的清单和成片放在同一期目录。

## 平台发布文案

每期分别写抖音、小红书、B 站的发布标题、正文和相关话题标签。参考[本期三平台文案](cases/today-advice/发布文案.md)。从真实使用场景或困惑切入，写清操作路径和用户能看到的结果。功能名和按钮名按录屏核对，发布标题可与片头、封面上的文字分别撰写。

- 抖音用一句问题或动作切入，正文简短，直接说明怎么操作和能看到什么。
- 小红书先写具体场景，单独列出操作路径，再补充功能看点和可用的后续操作。
- B 站用可搜索的功能名写教程标题，简介交代演示范围、操作路径和适用人群。

## 导出与验收

- 输出小红书 3:4、抖音 9:16、B 站 16:9 视频。旁白以剪后动作和结果为节拍，中文在上、英文在下，检查标记、定格和字幕是否同步。
- 输出小红书 3:4、抖音竖版 3:4 和横版 4:3、B 站 4:3 封面。使用抽帧确认过的真实 UI 帧，独立摆放「教程」。直接复用原版 Logo 和字标，具体素材和合成顺序见[系列规范](references/series.md)。
- 用 `ffprobe` 检查视频画幅、时长与音轨，抽查每个版本的片头、关键点击、剪点、稳定结果和结尾。检查点击位置、字幕边界、品牌素材、封面比例及手机 UI 小图可读性，播放最终视频检查等待是否干净、转场是否连续。发布素材前确认镜头和封面没有露出不宜公开的账号或健康数据。
- 给用户列出视频、封面、三平台发布文案和镜头清单的实际文件路径。发布或上传由用户另行指定。
